# 摄入知识即备份到 jsonl，向量库不作为唯一真相

通过 `/admin/parse-url` → `add_fragments` 摄入的知识（写本 ADR 时 156 条，占全库 94%）
此前只存在于 `backend/chroma_db/` 向量库一份，没有源文件、没有备份。

> 补记（2026-09）：那 156 条是本 ADR 落地之前摄入的，`ingested.jsonl` 对它们没有生效。
> 它们属于测试期数据，上线时不迁移、直接放弃；生产库从空开始，备份自第一条摄入即生效。

## 风险（与「删不删」无关）

- 这批知识多来自微信公众号，原文抓不回第二次。
- `scripts.ingest`（`store.ingest()`）会从 `corpus/*.md`（仅 10 个种子文件）
  全量重建、抹掉全部摄入知识；任何人误当成「刷新知识库」跑一次即全部丢失。
- 向量库 sqlite 文件损坏 / 误删 / 部署覆盖 → 一份即全部。

## 决定

`add_fragments` 成功写入后，把片段（text + meta）以 append 方式同步写一份到
`ingested.jsonl`（纯文本、可 grep）。向量库随时可从这份 jsonl 重建。
向量库不再是唯一真相，jsonl 是可离线保存的备份源。

落盘位置是 `config.DATA_DIR`（默认即 `backend/`，容器部署时由 `DATA_DIR` 环境变量
指向挂载卷）。它与三个 sqlite 同属「可变状态」，必须和它们一起备份——放 `corpus/`
会被镜像里的种子语料覆盖。

## 后续（本 ADR 未强制，但相关）

- 建议给 `store.ingest()` 加护栏：检测到库中存在带 url 的摄入知识时拒绝无参执行，
  防止误触发清空。
