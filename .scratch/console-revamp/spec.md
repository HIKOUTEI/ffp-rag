# 控制台视觉重构

把控制台从「单列七张卡片一路滚到底」改成分区式管理台。
**目标是更华丽，不是更简洁**——不削减任何现有功能，不减少信息密度。

## 为什么现在做

`frontend/CLAUDE.md` 写着「改动时不要顺手重构」，同时写着「真要拆分请单独开一个
`.scratch/` issue 讨论，不要夹带在功能改动里」。这份 spec 就是它说的那个 issue：
一次纯结构与视觉的改动，不夹带任何功能变更。

现状的问题不在配色——控制台早就是深色玻璃拟态了。问题在信息架构：
七块互不相关的功能挤在 `max-w-3xl`（768px）一列里，桌面上右边三分之二是空的。

## 术语

统一叫**控制台**。此前同一个东西有四种叫法（「后台管理页面」「管理后台」
「控制台」「console」），`CONTEXT.md:140` 已在用「控制台」，构建产物也是 `/console/`，
以它为准。词条补进 `CONTEXT.md`。

## 导航结构（契约）

```
工作台
  ▸ 入库 + 问答        ← 落地页，双栏并排
知识维护
  ⚑ 体检
  ⚠ 纠错   (待处理数角标)
  ⌸ 管理
系统
  % 返现规则
────────────────
● 已连接 / ○ 未配置令牌   ← 侧栏底部常驻状态栏，非导航项
```

分组依据不是新发明的，是代码里已有的事实：`showManage` / `showCorr` / `showRules`
三块默认 `useState(false)`（收起），体检要点按钮才跑，**常驻可见的只有令牌、入库、问答**。
日常主流程是「粘 URL → 入库 → 立刻问一句验证进没进去」。

**入库与问答必须并排**，这是工作台存在的全部理由——现在验证一条刚入库的知识要滚屏。

## 分区主题色（契约）

代码里已经散着六个强调色，但没有约定：teal 恰好是体检按钮、rose 恰好是纠错角标、
emerald 恰好是规则版本号。**是巧合，不是规则。** 这次把它扶正：

| 分区 | accent | 依据 |
|---|---|---|
| 工作台 · 入库 | `sky` | 现有解析按钮就是 sky-500 |
| 工作台 · 问答 | `violet` | 现有发送按钮就是 violet-500 |
| 体检 | `teal` | 现有体检按钮就是 teal-500 |
| 纠错 | `rose` | 现有待处理角标就是 rose |
| 管理 | `amber` | 剩下的唯一未被占用的暖色 |
| 返现规则 | `emerald` | 现有版本号徽章就是 emerald |

**约束：一页只出一个 accent。** 否则六个色同屏会花。状态色（成功绿、危险红、
警告黄）不算 accent，照常用。

### 实现上唯一的硬性要求

Tailwind 3 扫的是**源码里的字面字符串**。`` `bg-${accent}-500` `` 会被整个 purge 掉——
构建不报错，运行时静默掉色。所以 accent 必须是一张**写死完整类名**的查表
（`src/theme.ts`），不许拼接。

## 组件边界（契约）

30 个 `useState` 和所有 handler **原位留在 `App.tsx`**，只把 JSX 切出去，靠 props 传。

这么切的理由：逻辑零改动就不可能改出行为 bug；状态在父级，子组件卸载也不丢，
**切页时规则编辑器里那份没保存的 JSON 草稿不会丢**。
代价是 `App.tsx` 仍有约 420 行（全是状态与 handler），props 列表长。

```
src/
  App.tsx              ← 状态与 handler，原位不动
  theme.ts             ← accent 查表（完整类名）
  layout/
    Shell.tsx          ← 侧栏 + 主区骨架 + 分区光晕
    Sidebar.tsx        ← 导航 + 底部令牌状态栏
  sections/
    Workbench.tsx      ← 入库 + 问答双栏
    Health.tsx
    Corrections.tsx
    Manage.tsx
    Rules.tsx
```

令牌不是 section——它是侧栏底部的常驻状态栏，点开就地展开输入框。
理由：改成侧栏导航后它藏了两层，而新环境第一次打开时它是**唯一**的出路
（`api.ts` 里除问答外所有请求都带 `Authorization`）。

## 窄屏

`<1024px` 侧栏收成抽屉（汉堡按钮），工作台双栏堆叠。
**不**为表格与 JSON 编辑器做窄屏专项重排——那两件事在手机上本来就不该做，
移动端场景已由小程序承担。

## 依赖

新增 `lucide-react`（图标）。Unicode 符号（⚑ ⌸ ◷）跨平台笔画粗细不一致，会毁掉质感。

**必须同时提交 `package-lock.json`。** Jenkins 跑的是 `npm ci`，lock 与
`package.json` 不同步会直接让构建失败；构建容器还限了 `--memory 900m`，
不要引入重依赖（图表库这类在此约束下要单独评估）。

## 不做什么

- 不动 `api.ts` 的任何契约
- 不动后端
- 不改任何业务逻辑、请求时机、错误处理
- 不加新功能、不删现有功能
- 不做总览/仪表盘页（需要先想清楚放哪些指标，且要引图表库，与 900m 内存约束冲突）

## 验证

前端没有测试框架，能给的闸门只有：

```bash
npx tsc -b        # 类型
npm run lint      # oxlint
npm run build     # 构建通过
```

**「七个区的交互都没改坏」这条机器验证不了，必须人工点一遍。**
按 `Jenkinsfile`，改动只碰 `frontend/` 时只触发控制台构建，不动后端与数据。
