# 03 · 坐标转换 WGS84 → GCJ-02

Status: done

## 任务

新增 `app/rail/geo.py`，把 GTFS 的 WGS84 坐标转成微信小程序 `<map>` 用的 GCJ-02。

**不转的后果**：整体偏移 300~600 米，车站标记会落在铁轨旁边的居民楼上，
用户一眼就能看出错位。

## 实现

- 标准 WGS84 → GCJ-02 算法（`transformlat` / `transformlon` + 克拉索夫斯基椭球参数）。
- **境外判定**：算法对中国境外坐标应原样返回。全国铁路站点都在境内，
  但仍要保留这个分支，避免边境站（如满洲里、凭祥）附近的异常输入被错误偏移。
- **在哪转**：在接口返回时转，**不在同步时转**。`station` 表保持 WGS84 原值，
  理由是原始数据保真——将来若接入非腾讯地图（iOS 用高德/苹果地图）需要不同坐标系，
  或要做距离计算（必须用 WGS84），都不用回头改库。
- 提供 `wgs84_to_gcj02(lat, lon) -> (lat, lon)` 与批量版本。

## 验收

- 北京南站 WGS84 `(39.8634831, 116.3723994)` → GCJ-02 `(39.864866, 116.378617)`，
  偏移 553m。（已用标准算法实算核对，可直接作为单测基准。）
- 境外坐标（如东京 `(35.68, 139.76)`）原样返回。
- `station` 表中存的仍是 WGS84 原值。

## Comments

### 2026-09-17 实现完成

`backend/app/rail/geo.py`。实跑核对，验收值精确命中：

```
北京南 WGS84 (39.8634831, 116.3723994) → GCJ-02 (39.864866, 116.378617)，偏移 552.5 m
东京 (35.68, 139.76) 原样返回
(None, None) 原样返回
```

除 spec 要求的两个函数外，多加了两个：

- `convert_points(points)` —— 就地转换一组 dict，接口层直接套在 `store.get_stops()` 上。
- `distance_m()` —— 球面距离。**必须传 WGS84**。加它一是为了核对上面那个 553m 验收值，
  二是 issue 07 若退化到"按坐标估算里程"时要用。日常不该用它算里程，
  GTFS 自带的营业里程才与票面一致。

`station` 表仍是 WGS84：同步脚本不 import `geo`，转换只发生在接口返回时。
