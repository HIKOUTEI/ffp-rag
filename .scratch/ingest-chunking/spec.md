# Spec: 修复长文切分导致的列表截断 / 序号粘连

## 背景（真实案例）

万豪攻略 `https://mp.weixin.qq.com/s/dFpY5zreK2jK_UAGwgFfaw` 入库后，
里程碑奖励段落只留下：

> `1.50N礼遇：5晚套房券（NUA）：目前已涵盖丽思卡尔顿和艾迪逊`

暴露两个 bug：

1. **列表被块边界截断**：`_split_text`（`app/ingest_url.py`）按 `max_len=1000` 切块并行解析，
   里程碑列表正好被拦腰切断——`2.75N 礼遇` 那一档整档丢失（不是切错，是压根没被 AI 提取进来）。
2. **序号与数字粘连**：`1.` + `50N` 被读成小数 `1.50N`。`PARSE_SYSTEM` 里**已经有**一条
   专门的 anti-`1.50N` 指令（68–70 行），但仍未生效。

（该案例已用 `update_doc` 手工修好，本 spec 针对**根因**，让以后每篇长文都不再犯。）

## 目标

长文摄入时，语义完整的列表/小节不被块边界切断；序号不再和内容数字粘连。

## 约束 / 现状

- 切分入口：`app/ingest_url.py` 的 `_split_text(text, max_len=1000)` → `parse()` 并行 `_parse_chunk()`。
- 公众号正文常只有单换行；`_split_text` 已有「双换行切不动退单换行」逻辑。
- 抓取正文上限 12000 字（`fetch` 截断），单块解析用 LLM（`CHAT_MODEL`, JSON 输出）。
- prompt 已含数字/步骤逐字保留 + anti-`1.50N` 指令，但对被截断的块无能为力。

## 明确不做

- 不重构整个摄入管线；不改 embedding / 检索逻辑。
- 不追求通用 Markdown 解析器，够用即可。
