# Spec: 奖赏钱记录（月结账本 + 上限与门槛预测）

## 背景

香港汇丰的信用卡回赠以**奖赏钱 / RewardCash（RC）**结算，$1 RC = HK$1。
Reward+ App 能看到余额和分类，但看不到**「我离各项上限还有多远」**——
而那些上限和门槛恰恰决定了下一笔该怎么刷：

- 最红自主奖赏额外 5X 只覆盖首 HK$100,000 签账（历年）
- 内地／澳门扫码 +2% 只覆盖首 HK$80,000（促销期 2026-07-01～12-31）
- 内地餐饮 +3% 要求**每历月**内地累计签账 ≥ HK$1,200 才触发，且每月封顶 $80 RC

这是本项目第三条**不属于 RAG 问答**的产品线（前有铁路乘车记录）。
它不进向量库、不参与检索，`credit_card` 那个 `domain` 指的是信用卡**知识**，
与用户本人的账本无关。

## 目标

**记录不是目的，预测才是。** 录入成本必须压到「一个月抄一次」，
否则没人会长期用——用户不可能消费一次就来记一次。

四项预测：

| 预测 | 数据来源 | 能否只靠月结 |
|---|---|---|
| 各项上限还剩多少 | 月结 RC ÷ 费率 → 签账额 | ✅ |
| 本月门槛凑到了没 | 逐笔签账记录 | ❌ **只能靠逐笔** |
| 期末／年底预计拿多少 | 历史速率外推 | ✅ 需 ≥2 个月 |
| 即将到期的 RC | 照抄，不推算 | ✅ |

## 设计决策（经 grilling 敲定）

### 1. 账户级，不是卡级

**最红自主奖赏的类别跟人不跟卡**——名下所有汇丰卡共用同一个自选类别、
同一份 HK$100,000 年度额度；扫码 +2% 的 HK$80,000 按「同一身份证／护照下
主卡 + 附属卡合并」计算。Reward+ 给出的也是账户级汇总。

所以**上限追踪天然不可能按单卡做**。Pulse 只是「目前名下唯一一张卡」，
降为逐笔签账记录上的一个可选标注。

> 曾经的设计是「Pulse 返现试算器」，在这一条上崩掉：
> `1,299 RC ÷ 2% = Pulse 签账 HK$64,950` 是错的，那是**所有卡合计**。

### 2. 月结汇总为主，逐笔为可选（详见 ADR-0010）

一月一条，照 Reward+ 抄。逐笔想记就记，唯一不可替代的价值是**月中推算门槛**。

### 3. 流量与存量在类型上分开

月结记录里混着两类性质完全不同的字段：

| 流量（可跨月加总） | 存量（快照，**不可加总**，只取最新） |
|---|---|
| 当月各类别赚取 RC | 期末余额、即将到期 RC + 到期日 |

必须落到**两个嵌套对象** `flow` / `stock` 上，不能靠注释约束——
否则任何「近 N 个月汇总」的代码都会顺手把余额也加起来。

### 4. 只有费率型类别能反推签账额

「优惠 800 RC」看起来正好等于迎新的 $800，但那是**数字凑巧相等**。
「优惠」是杂项桶（迎新、生日礼遇、限时加码都可能落进来），而且是**定额**不是费率。

→ 规则标 `kind: rate | flat`。**定额型不进任何上限反推**，除以任何费率都是垃圾数字。

### 5. 外推只吃经常性收入

用户截图里 3,023 RC 中有 **800 是迎新**（一次性）。按速率外推若不剔除，年度预测直接虚高。
且 +2% 扫码与 +3% 餐饮 **2026-12-31 到期**，不能拿含促销的速率往促销结束后推。

→ 规则标 `recurrence: recurring | one_off`，外推只吃 `recurring`。

### 6. 四种周期口径并存，起止日必须逐条显式记录

| 上限 | 周期口径 | 本期起止 |
|---|---|---|
| 最红自主奖赏 HK$100,000 | `calendar_year` 历年 | 2026-01-01 ～ 12-31 |
| 扫码 +2% 首 HK$80,000 | `promo_period` 促销期 | 2026-07-01 ～ 12-31 |
| 内地餐饮 $80 RC | `calendar_month` 历月 | 每月 1 号归零 |
| 内地餐饮 $480 RC | `promo_period` 促销期 | 2026-07-01 ～ 12-31 |
| Travel Guru 600/1,400/2,200 RC | `membership_year` 会籍年 | 登记日起算，因人而异 |

⚠️ 历年与促销期**都在 12-31 结束**。这个巧合会掩盖 bug：
写死一个 12-31 现在看全对，跨到 2027-01 全错。**周期必须是规则上的显式字段。**

### 7. 规则由后端下发（详见 ADR-0009）

促销 2026-12-31 到期，小程序发版要过审核。规则打包进小程序意味着
每次促销换期都要发一次版。

### 8. 控制台只维护规则，不碰个人数据

`frontend/` 是「给我自己用的单页管理控制台」，走已有 `ADMIN_TOKEN`。
个人记录只在小程序——录入场景本来就是「手机上开 Reward+ 抄数」。

> 曾计划做「小程序生成配对码 → 网页兑换 token」让控制台也能看个人总览。
> **已砍**：只读总览的边际价值不抵一套登录态 + 一条 ADR 的成本。

### 9. 确信度降级为说明字段

四档确信度（`official` / `user_verified` / `unverified` / `unavailable`）原本是为
「下一笔该怎么付」设计的。工具改成账本后，规则表主要提供费率与上限，这些都是 `official`，
`unverified` 失去主要用武之地。保留在规则数据里，不进 UI 主干。

## 规则数据（2026-09-20 整理）

来源：三份官方 T&C PDF + 最红优惠网 + 银联公告。详见 `issues/02`。

| 规则 | 类型 | 费率/定额 | 上限 | 登记 | 确信度 |
|---|---|---|---|---|---|
| 基本奖赏钱 | rate / recurring | 0.4% | 无 | 否 | official |
| 最红自主奖赏「赏世界」 | rate / recurring | +2% | 签账 HK$100,000 · 历年 | **要** | official |
| 内地澳门二维码或流动支付 | rate / recurring | +2% | 签账 HK$80,000 · 促销期 | 否 | official |
| 最红签账奖赏—内地餐饮 | rate / recurring | +3% | 奖赏 $80·历月 + $480·促销期 | **要** | official |
| Travel Guru | rate / recurring | +3/4/6% | 奖赏 600/1,400/2,200 · 会籍年 | **要** | **unavailable** |
| 迎新 | flat / one_off | $800 或 $200（+$200 分期） | 一次 | 否 | official |

横切约束（进规则的 `note`，影响逐笔记录的归类，不影响月结）：

- **DCC 陷阱**：刷卡时选港币结算，同时吃掉扫码 +2% 和 Travel Guru 的 +6%。
- **扫码定义**：仅汇丰 Reward+ App 或云闪付 App 扫码，**仅主卡**；
  流动支付 = Apple / Google / Samsung Pay。**支付宝、微信支付明列排除**。
- **AlipayHK 能绑 Pulse**（[银联 2024-09-26 公告](https://cn.unionpay.com/upowhtml/cn/templates/newInfo-nosub/7885004da382485e8bde5a0ba000fdd3/20240926120739.html)，
  AlipayHK 官方 FAQ 称只支持 Visa/Mastercard，**已过时**）。但它走港币钱包换汇、
  也不在「二维码支付」定义内，两条理由都拿不到 +2%，只有基本 0.4%。
- **基本 0.4% 所有付法都有**。条款排除的是「购买及／或充值储值卡或电子钱包」
  这个行为本身，不是「用电子钱包付款」。
- **美团到店买单按餐饮 MCC 计**，能吃到 +3%（`user_verified`，用户实测）。
- **美团／大众点评 RMB 160 那个促销本卡不适用**——限汇丰 Mastercard 信用卡或扣账卡，
  Pulse 是银联。

## 待确认事实（写进规则数据标记，不阻塞开发）

1. **附属卡是否有独立的 HK$100,000 额度**。[官方条款](https://www.redhotoffers.hsbc.com.hk/tc/rewards/red-hot-rewards-of-your-choice/)
   未明写，[MoneyHero](https://www.moneyhero.com.hk/zh/credit-card/blog/%E8%B3%BA%E7%9B%A1%E7%8D%8E%E8%B3%9E%E9%8C%A2-hsbc%E5%8C%AF%E8%B1%90%E4%BF%A1%E7%94%A8%E5%8D%A1%E6%9C%80%E7%B4%85%E8%87%AA%E4%B8%BB%E7%8D%8E%E8%B3%9E%E6%94%BB%E7%95%A5)
   称「附属卡持卡人如本身无独立基本卡，可能有独立额度」。目前单卡不受影响。
2. **内地餐饮 +3% 的 RC 落在 Reward+ 的哪个类别**。若落在「最红自主奖赏」里，
   会污染该类别的 ÷2% 反推。第一版先当独立类别处理，用户抄数时若发现没有这一项需回填此处。
3. **奖赏钱的具体有效期规则**（[条款页](https://www.hsbc.com.hk/zh-hk/credit-cards/rewards/terms/)）。
   本期不受影响——到期数直接抄，不推算。
4. **Travel Guru 2026 登记窗口**。历史窗口 2023/9/1–2024/4/7、2024/9/1–10/31、
   2025/10/1–10/31，官方页最后更新 2026-04-01 未见 2026 窗口。规则状态先置 `unavailable`。

## 明确不做

- **不做「刷之前算一笔」的试算器**。曾经的设计方向，已废弃——用户要的是账本+预测。
- **不做用户上报实测结果**。确信度由维护者手工维护，不做众包校正队列。
- **不做账单 OCR / 截图识别**。月结只有 4~6 个数字，手抄比识别可靠。
- **不做汇率服务**。逐笔记录的港币折算由用户填，或按 1:1（人民币／澳门币）粗估。
- **不接汇丰 API**。没有对公开发者的接口。
- **不做多卡分账**。见决策 1——上限本就是账户级，分卡反而算不出进度。
- **不把奖赏钱数据接入 RAG 问答。**

## 上线前必办

- **隐私**：奖赏钱余额与消费记录属个人财务信息，敏感度高于乘车记录。
  小程序《用户隐私保护指引》需增列收集类型。
- **删除与导出**：沿用 rail 那套（`GET /export`、`DELETE /account`），
  本模块的数据必须一并纳入导出与注销的清理范围——**别漏表**。
